# Кишт — план разработки

## Продукт
Веб-лаборатория для Таджикистана: пользователь выбирает участок, почву, культуру и доступную воду, смотрит сезон в 3D, сравнивает текущий севооборот и две альтернативы. 3D визуализирует модель, а не гарантирует урожай. Основной результат — объяснимое сравнение последовательностей культур.

## Фаза 1. Вертикальный прототип (текущая)
React + TypeScript + Vite; Three.js через React Three Fiber и Drei; CSS; Lucide. Один участок, три условных культуры, три почвы, полив, температура, дождь, шкала сезона, визуальные риски, сравнение планов. Все модельные параметры помечены как демонстрационные. Готовность: настройки меняют расчёт и сцену, сборка проходит, можно открыть ссылку.

## Фаза 2. Участок и местная агрономия
Выбрать пилотный район и реальный тип хозяйства с пользователем. Подтвердить культуры, сорта, даты посева/уборки, текущий севооборот, наличие орошения, характеристики почвы. Добавить «не знаю» с диапазонами неопределённости. Получить проверку местного агронома. Критерий: документированные источники всех параметров, отсутствие универсальных рекомендаций для всей страны.

## Фаза 3. Данные NASA
NASA POWER: дневные температура и осадки; затем излучение, влажность воздуха и ветер при необходимости выбранной модели. Сейчас используется среднее исторического периода 2024-04-01—2024-07-29, это сознательное ограничение прототипа. Далее хранить дневной ряд, единицы, координаты, исходный ответ, дату получения, разрешение, пропуски и флаги качества. Добавить многолетний диапазон и исторический сухой год. Данные SMAP/GPM/Landsat добавлять только для конкретного показателя и после проверки покрытия/масштаба. Не превращать крупную сетку в фиктивные точные зоны поля. Критерий: воспроизводимый сценарий из реального источника и честная обработка отсутствующих данных.

## Фаза 4. Расчётная модель
Python + FastAPI и pytest вводить при переходе к научной модели; текущий чистый TypeScript-модуль отделён от визуализации. Выбрать документированный метод водного баланса и эвапотранспирации, подключить культурные коэффициенты и фенологию. Рассчитывать по дням осадки, эффективный полив, испарение/транспирацию, дренаж, доступную влагу. Начальные условия, единицы и границы обязательны. Сверить с эталонными примерами, провести анализ чувствительности. Уровень уверенности зависит от качества данных, не от ответа языковой модели. Урожайность и доход добавлять только после калибровки.

## Фаза 5. Севообороты
Моделировать 3 последовательности по 3 сезона, включая текущую. Связать сезоны состоянием почвы и календарём; учитывать периоды без покрытия. Ввести ограничения воды, оборудования и предпочтений. Почвенные эффекты сначала качественные с источниками; численные эффекты только при наличии модели. Показывать преимущества, компромиссы, неопределённость и основания каждого плана.

## Фаза 6. 3D
Стилизованное поле; отдельные стадии посева, всходов, развития и созревания; вода в бороздах; дождь; разрез и корни; видимые маркеры водного/теплового стресса. Blender/glTF при необходимости; инстансинг для множества растений, общие геометрии и материалы, уровни качества, ограниченный DPR. Сцена получает данные только из результата модели. Камера ограниченная, управление мышью/пальцем, остановка времени. Текстовый эквивалент рисков и режим уменьшенного движения. Критерий: плавная работа на целевых устройствах и понятное соответствие картинки расчёту.

## Фаза 7. Интерфейс и локализация
Русский и таджикский с проверкой носителем языка. Большая сцена, 3 группы настроек, подробности по запросу. MapLibre для выбора участка; SQLite/JSON-кэш или Worker-хранилище после выбора серверной архитектуры. Сохранение сценариев сначала локальное. Не требовать регистрацию для демонстрации. Проверить клавиатуру, контраст, узкие экраны, отсутствие горизонтального скролла.

## Фаза 8. Проверка
Тесты баланса воды, границ, пустых данных, единиц и повторяемости. Интеграционные тесты NASA с сохранёнными примерами, отказ сети без подмены источника. Браузерный проход: выбрать участок → изменить почву/культуру → запустить → полив → перемотка → сравнение. Проверить, что переключение региона сбрасывает чужие данные. Замерить скорость загрузки и FPS; проверить WebGL fallback. Агрономическая валидация — отдельная от технических тестов.

## Фаза 9. Доставка и хакатон
Статический фронтенд — Sites, приватный по умолчанию. Python-сервис при появлении публикуется на совместимом отдельном хостинге; Cloudflare Worker не запускает обычный FastAPI-процесс. Секреты только на сервере. Подготовить кэш NASA для демонстрации с датой и источником, резервное видео, README, список источников, лицензии ассетов и 3-минутный питч. Сценарий: фермер → недостаток воды → текущий план → две альтернативы → объяснение NASA → ограничения.

## Приоритеты
P0: понятная сцена, изменение условий, проверяемые данные, три плана, объяснения, стабильная демонстрация.
P1: дневные данные, локальные культуры, связанная модель сезонов, таджикский, карта, сохранение.
P2: дополнительные спутниковые слои, поясняющий ИИ по результатам расчёта, экспорт.
Камера/диагностика почвы по фото, реалистичная гидродинамика, гарантированный урожай и 3D всей страны в первую версию не входят.

## Что понадобится от пользователя
Пилотный район, знакомые культуры и текущее чередование, сведения о поливе, длительность хакатона и состав команды. Для текущего запроса NASA POWER пользовательский ключ не используется. Дополнительные сервисы могут потребовать учётную запись; секреты в чат не запрашивать.
